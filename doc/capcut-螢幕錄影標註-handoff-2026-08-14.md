## 🔍 內建功能調查結果（本次最有價值的產出）

原本的做法是「自己產生 PNG 圖層再疊上去」，經使用者質疑後實際進 CapCut 逐項驗證，**確認 CapCut 有內建功能，而且簡單很多**。

### 已在本機 CapCut 實際確認存在的功能

| 需求 | 內建做法 | 驗證結果 |
| --- | --- | --- |
| 紅框 | **貼圖 → 形狀 → 矩形外框** | ✅ 存在。另有圓形、箭頭、直線、梯形、平行四邊形、自訂多邊形 |
| 馬賽克 | **特效 → 搜尋 `mosaic`** | ✅ 有「馬賽克／馬賽克還原／藍色馬賽克／馬賽克閃電／馬賽克人物投影／馬賽克變焦」等多款 |
| 限制馬賽克範圍 | **影片 → 遮罩轉場 → 矩形遮罩** | ✅ 存在（線性／鏡面／圓形／矩形／愛心／星形） |
| 跟著移動的目標 | **疊加片段 → 追蹤 → 動態追蹤** | ✅ 存在（**只有疊加片段有「追蹤」分頁，主影片軌沒有**） |

### 正確的內建流程

**紅框（約 30 秒）**

1. 貼圖 → 形狀 → 矩形 → 拖到時間軸（會自動建立貼圖軌）
2. 在播放器裡直接拉大小和位置
3. 右側「向量影像」屬性面板：**取消勾選「填滿」** → **勾選「描邊」** → 顏色設紅色、粗細設 4

> 形狀貼紙是**真正的向量物件**，屬性面板有：大小（寬/高可獨立）、縮放、位置、旋轉、不透明度、填滿（顏色+不透明度）、描邊（樣式/顏色/粗細/不透明度）、圓角半徑、陰影（顏色/距離/角度）。比自製 PNG 彈性大得多，隨時可改。

**局部馬賽克（約 1 分鐘）**

1. 選主影片片段 → `Ctrl+C` → `Ctrl+V`（CapCut 會**自動開新軌道**放複製片段 —— 第 8 章做「文字穿插人物背後」時已用過這招）
2. 對複製的那層套用「馬賽克」特效
3. 該層 → 影片 → **遮罩轉場 → 矩形遮罩**，把遮罩拉到要打碼的區域
4. 完成 —— 只有遮罩內是馬賽克，其餘顯示底層原畫面

> **比 PNG 做法好的關鍵**：它是**即時運算**的，會跟著影片內容走；PNG 是把某一格的畫面凍在上面，只在內容靜止的區間有效。

### ⚠️ 三個實測踩到的坑

1. **素材庫搜尋框中文搜不到**。輸入「馬賽克」出來一堆不相干特效，輸入英文 `mosaic` 才正確列出全部馬賽克系列。**找素材一律用英文關鍵字**。
2. **數值欄要點面板其他地方才會提交**。向量形狀的「大小」「位置」欄位輸入數值後，只按 `Tab` 會顯示新值但**畫面不會更新**；必須再點面板空白處才真正套用。（附帶：影片疊加片段的「位置 X/Y」欄實測**完全無效** —— 欄位顯示新值，但算圖與 draft JSON 的 `clip.transform` 都不變。）
3. **位置 X/Y 的單位不是畫布像素，且 Y 軸方向相反**。依畫布座標算出 X=-835 / Y=160 填入，實際只移動約一半距離，且 Y 往上而非往下。要用數值定位必須先試一次抓比例，否則直接用滑鼠拖比較快。

## ❓ 未完成的實驗：動態追蹤能不能跟住捲動的文字

**這題還沒有答案，是接手後最值得先做的事。**

### 為什麼重要

螢幕錄影的核心痛點是**文字會一直往上捲**，靜態標註只在文字停在原位的那幾秒有效。目前三個解法：

| 解法 | 狀態 | 代價 |
| --- | --- | --- |
| **動態追蹤** | ❓ **未實測** | 若可行，這是最聰明的解 —— 標註自動跟著文字捲動，不用定格、不用切段 |
| **定格（定鏡）** | ✅ 已驗證可行 | 影片變長，後面所有內容往後推 |
| **錄影時就停一下** | 最省事 | 需事前規劃，無法補救既有影片 |

### 我的推測（純推論，未驗證，不可當結論）

**可能失敗**。理由：動態追蹤是為人臉、車牌這類有明顯輪廓、連續移動的物體設計的；終端機文字是等寬灰白字、對比低、而且是**跳躍式捲動**（新行輸出時整段瞬間往上跳，不是平滑位移），追蹤器通常需要連續運動才鎖得住。

**但這只是推測，沒實測就不算數。**

### 建議的測試方法

在**定鏡之後**的區段做（55.467s 之後影片恢復正常播放，且「名單載入」會在 56.267s 捲走）：

1. 貼圖 → 形狀 → 矩形，拖到疊加軌，時間設 55.5 → 58.5s
2. 在播放器裡把矩形放到「名單載入」上
3. 右側面板 → **追蹤 → 動態追蹤**，框選要追蹤的區域
4. 逐格檢查 56.267s 前後：矩形有沒有跟著文字往上走？

**判讀標準**：若矩形在文字跳動時能跟上（或最多延遲 1-2 格），就算可用；若完全不動或亂飄，就是失敗，之後一律用定格。

## 技術細節（要復現或除錯時用）

### 座標轉換（實測值，非理論值）

主影片 seg1 的 `clip.scale = 0.98`，但**實際算圖位置與「以畫布中心等比縮放」的理論模型對不上**（垂直方向差約 60px）。經實測反推的仿射轉換為：

```
canvas_x = 0.984 × source_x + 26.2
canvas_y = 0.980 × source_y + 70.3
```

驗證方式：把已知正確的紅框一起疊進模擬合成圖，紅框落點正確即代表轉換無誤。

> ⚠️ **不要用 draft JSON 的 `target_timerange`/`source_timerange`/`speed` 換算去抽畫格量座標** —— 內容（時間）對得上，但空間位置會差幾十像素。座標一律實測校正。

### 產生標註 PNG 的 ffmpeg 指令

**紅框**（`replace=1` 必加，否則 alpha 為 0、在 CapCut 裡完全看不見）：

```bash
ffmpeg -f lavfi -i "color=c=black@0.0:s=1920x1080:r=30,format=rgba" \
  -vf "drawbox=x=101:y=675:w=122:h=49:color=red@1.0:t=4:replace=1" \
  -frames:v 1 -y out.png
```

**馬賽克＋紅框合併**（先鋪馬賽克再疊框）：

```bash
ffmpeg -i frame.png -filter_complex \
 "[0]crop=375:620:0:0,scale=27:44,scale=369:608:flags=neighbor,format=rgba[mos]; \
  color=c=black@0.0:s=1920x1080,format=rgba[bg]; \
  [bg][mos]overlay=26:70,drawbox=x=70:y=678:w=110:h=45:color=red@1.0:t=4:replace=1" \
 -frames:v 1 -y out.png
```

**驗證 alpha**（第四個值必須是 255，若為 0 就是踩到 `replace` 的坑）：

```bash
ffmpeg -i out.png -vf "crop=1:1:<邊框上一點>" -f rawvideo -pix_fmt rgba - | od -An -tu1
```

### CapCut 操作技巧

- **時長修剪用播放頭吸附**：先點尺規把播放頭移到目標時間（讀時間碼確認），再拖片段邊緣過去會精準吸附，實測誤差 0
- **多圖層同步**：第二個疊加片段拖進時間軸時會**自動吸附到既有片段的邊緣**，起點可一次到位
- **定鏡不會位移疊加軌**：主影片插入定鏡後，疊加軌上的圖層時間**不會**跟著推移（好處：既有標註不會被破壞；壞處：要自己手動拉長）
- **點時間軸主體區域會移動播放頭**（不只尺規），要選片段請直接點片段本身
- **修剪前先調時間軸縮放**：53 秒處在全覽比例下只有 16 px/秒（1 影格 = 0.5px），根本無法精修；調到約 64 px/秒（1 影格 ≈ 2.1px）才動手
