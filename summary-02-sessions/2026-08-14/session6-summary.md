## 關鍵技術筆記

### ffmpeg 產生透明標註圖層

- **`drawbox` 必加 `replace=1`**：預設會與底層 alpha 混合，在全透明底上畫會寫入 RGB 但 alpha 仍為 0，成品在 CapCut 裡完全看不見。驗證方式：`ffmpeg -i out.png -vf "crop=1:1:x:y" -f rawvideo -pix_fmt rgba - | od -An -tu1`，第四個值必須是 255
- 局部馬賽克：`crop → scale 縮小 → scale 放大(flags=neighbor)` 三段即可，不需 PIL

### 座標轉換（本 session 最耗時的坑）

主影片 `clip.scale = 0.98`，但**實際算圖位置與「以畫布中心等比縮放」的理論模型對不上**（垂直差約 60px）。實測反推的仿射轉換：

```
canvas_x = 0.984 × source_x + 26.2
canvas_y = 0.980 × source_y + 70.3
```

- **不可用 draft JSON 的 `target_timerange`/`source_timerange`/`speed` 換算去抽畫格量座標** —— 時間對得上，但空間位置差幾十像素
- 正確流程：先放一版進去 → 截圖 → **用已知尺寸的框本身當量測標尺**算播放器縮放比 → 量像素差 → 換算回畫布座標 → 重產。第二版即精準
- 驗證技巧：本地模擬合成時把**已驗證正確的紅框一起疊上去**當校驗基準，紅框落點對就證明轉換無誤

### CapCut 操作

- **「定鏡」不是「定格」**：freeze frame 在右鍵 → **編輯 →** 子選單內（同層有倒轉／鏡像／旋轉／裁切），第一層選單沒有
- **定鏡不會位移疊加軌**：主影片插入定鏡後，疊加圖層時間不變（好處：既有標註不被破壞；壞處：要自己拉長）
- **新結束時間 = 原結束時間 + 定鏡長度**（定鏡凍的是播放頭那格，該格已對位）
- **吸附**：第二個疊加片段拖入時自動吸附既有片段邊緣，起點實測誤差 0；修剪也靠播放頭吸附
- **素材庫搜尋只吃英文**（打「馬賽克」無結果，打 `mosaic` 才有）
- **數值欄**：向量形狀有效但**要點面板其他地方才提交**（按 Tab 不夠）；影片疊加片段的「位置 X/Y」**完全無效**（欄位顯示新值但算圖與 JSON 都不變）
- **位置 X/Y 單位不是畫布像素、Y 軸方向相反**
- **修剪前先調時間軸縮放**：53 秒處在全覽比例只有 16 px/秒（1 影格 = 0.5px），調到約 64 px/秒才能精修
- **點時間軸主體區域會移動播放頭**（不只尺規）

### git 大檔修復

已推送歷史乾淨 + 只有一個未推送 commit 時的最小修法：

```
git reset --soft HEAD~1     # 撤 commit，變更留暫存區（非 --hard，不刪檔）
echo "*.mp4" >> .gitignore
git rm --cached <大檔...>    # 只取消追蹤，磁碟檔案保留
git commit && git push       # 無需 force push
```

**關鍵認知**：`.gitignore` 只管未追蹤檔案，已 commit 的大檔加 gitignore 完全無效，push 一樣被擋。

### 它揭露了一個比本 session 記載更好的做法

本 session 記的局部馬賽克流程是「複製主影片到疊加軌 → 套馬賽克特效 → 加矩形遮罩」。
該筆記顯示**不必複製影片軌** —— **特效本身就能加遮罩，而且遮罩可以直接追蹤**：

```
特效分頁 → 搜尋 mosaic → 拖到特效軌
→ 選中特效 → 右側「遮罩」分頁 → 「＋ 新增遮罩」→ 矩形
→ 遮罩設定用數值定位（大小 300×680、位置 X 220 / Y −32）
→ 捲到面板底部「追蹤遮罩」→ 方向「兩者」→ 按「追蹤」
```

18 秒素材約 20–25 秒跑完，追蹤後遮罩位置逐格寫入關鍵影格（實測 0s/5s/10s/15s/19s 座標皆不同）。
**這條流程步驟更少、不產生多餘軌道，應取代本 session 記載的複製影片法。**
